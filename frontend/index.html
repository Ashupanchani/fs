💡 Top CIA Oral Questions & Direct Answers

Q1: Explain the architecture of this application.
This is a 3-tier full-stack web application built on the MVC (Model-View-Controller) design pattern:
  • Model: Mongoose schemas (Product, Cart, Order) define data structure and validation rules in MongoDB.
  • Controller: Business logic functions (e.g., calculating totals, deducting stock, seeding from external APIs).
  • Routes: Express routers mapping RESTful endpoints (GET, POST, PUT, DELETE, PATCH).
  • View: Responsive frontend communicating via asynchronous fetch() API calls.
Q2: How is MongoDB integrated with Node.js?
We use Mongoose, an Object Data Modeling (ODM) library for MongoDB and Node.js. mongoose.connect() establishes an asynchronous connection using the connection URI stored securely in .env. Mongoose models enforce schema validation and provide high-level CRUD methods like .find(), .findByIdAndUpdate(), and .deleteMany().
Q3: How are public free APIs utilized for products?
Our backend controller exposes POST /api/products/seed, which calls the free public FakeStore API (https://fakestoreapi.com/products) using native fetch. It transforms the incoming JSON into our Mongoose schema format, clears previous records, and saves them into local MongoDB using Product.insertMany().
Q4: What is the difference between PUT and PATCH?
PUT is used for replacing or updating an entire resource representation (e.g. updating all fields of a product or cart item quantity).
PATCH applies partial modifications to a resource (e.g., only updating the status field of an order without altering its items or customer info).
Q5: How does checkout ensure data consistency?
When POST /api/orders is triggered:
  1. It validates that the cart is not empty.
  2. Snapshots current item details (title, price, quantity) into the order.
  3. Decrements product stock using Mongoose $inc: { stock: -quantity }.
  4. Clears the cart with Cart.deleteMany({}) once the order is persisted.
Q6: What HTTP status codes are used and why?
  • 200 OK: Successful GET, PUT, PATCH, or DELETE request.
  • 201 Created: Successful POST request that created a new resource (e.g. product, cart item, order).
  • 400 Bad Request: Client sent invalid or missing payload data.
  • 404 Not Found: Resource with specified ID does not exist.
  • 500 Internal Server Error: Database or unhandled server exception.
